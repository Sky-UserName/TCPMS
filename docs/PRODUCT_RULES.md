# 业务规则与状态

## 1. 订单状态

~~~text
待支付
  -> 已支付·待确认
  -> 已取消

已支付·待确认
  -> 已确认·待入住
  -> 退款中

已确认·待入住
  -> 已入住
  -> 退款中

已入住
  -> 已完成

退款中
  -> 已退款
  -> 退款失败
~~~

后端状态枚举是唯一事实来源，用户端只负责中文显示和动作映射。不要在页面写一套独立状态机。

## 2. 库存

- 入住日期包含，离店日期不包含。
- 创建订单时按每个入住晚逐日锁定房型库存。
- 支付成功后锁定库存转为已售库存。
- 取消、支付超时或退款审核通过后释放库存。
- 具体房间/床位在办理入住时自动或手动分配。
- 同一门店、房型、日期只能有一条库存记录。
- 无有效经纬度的门店不参与附近距离排序，但仍可在普通列表展示。

## 3. 日期和人数

- 默认入住日期为明天，默认离店日期为后天。
- 离店日期必须晚于入住日期，至少一晚。
- 人数、床位、房间数在确认订单和 API 请求中保持一致。
- 日期选择页面只负责日期；人数、床位、房间数使用独立弹层。

## 4. 地图和定位

- 用户拒绝定位时仍显示全部营业门店。
- 地图服务端 Key 只放在后端配置。
- 地理编码失败不能阻止后台手动保存合法经纬度。
- 小程序只读取公开地图配置和门店坐标。

## 5. 用户端 UI 约定

- 页面整体使用蓝绿色主题。
- 主导航固定为：首页 / 门店 / 订单 / 消息 / 我的。
- 所有无数据场景使用 ProtoEmptyState 和统一图标。
- 顶部标题通过 ProtoHeader，正文通过 .proto-page 预留底部导航安全区。
- 列表卡片需要有加载、空状态、错误和成功四种可辨识状态。

## 6. 数据安全

- 身份证号必须加密存储，列表默认脱敏。
- JWT、微信支付证书、高德 Key、数据库密码不提交到前端。
- 门店、房型、库存、订单、退款、权限和坐标修改必须产生审计记录。
- 后台接口必须服务端校验角色和门店数据范围，不能只依赖前端隐藏按钮。
